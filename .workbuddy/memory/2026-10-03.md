## 本轮修掉的三个真实缺陷（重要，别重复踩）

1. **音频指纹的频带边界随采样率浮动** → 同曲不同码率识别失效。
   `log_band_edges(sample_rate)` 让 44.1kHz 覆盖 40–16kHz、22.05kHz 覆盖 40–11kHz，
   「第 k 条频带」在两个文件里对应的实际频率不同，轮廓不可比。
   实测相似度 0.9192 **低于默认阈值 0.92** → 开箱即用失败。
   修复：改为固定的绝对频率网格 `band_edges_hz()`（40Hz→16kHz 恒定），
   超出 Nyquist 的频带自然为空。相似度提升到 **0.9809**。
   顺带把「样本→轮廓」抽成 `ProfileBuilder`，使采样率无关性可被单元测试直接驱动。

2. **无 GUI 会话下回收站完全不可用**。`trash::delete` 在 macOS 借道 Finder 自动化，
   被 TCC 拒绝（`-10004 权限违例`）—— 而 CLI 恰恰是为 CI/CD 准备的。
   修复：`do_trash` 失败时降级为移入用户回收站目录
   （macOS `~/.Trash`、Linux `~/.local/share/Trash/files`），同名自动改名。
   仍然可恢复，绝不永久删除。

3. **感知哈希在 CLI 冒烟测试中返回 0 分组**（本轮开工时的待查项）。
   根因有两个，**都不是算法问题**：
   - fixture 用 `(x*2) % 256` 取模渐变造「相似图」，锯齿边缘 + 不同分辨率下
     折叠次数不同 → 频谱被撕碎，pHash 距离高达 28/63。改用多倍频 value noise（fbm）
     后，同一张图在 256/192/128 三种分辨率下 **pHash 距离全为 0**。
   - 更隐蔽的一点：流水线把**已进入精确重复组的文件从相似检测中排除**
     （`consumed` 集合）。所以相似测试图**必须是逐字节不同的**，否则会在精确阶段
     被消耗掉，感知阶段根本看不到它们。
   结论：pHash 算法本身经真实照片验证正确 —— 4096×2160 缩到 640×337、
   JPEG q35 重压、转 PNG，**距离全为 0**。

## 有价值的负向结论（避免过度设计）
- **不要把 dHash 也并入分组判定**。实测 15 张系统壁纸 105 对组合：
  纯 pHash **0 误判**；pHash OR dHash 会有 1 个误判
  （"Grid Magenta Light" vs "Grid Green Dark" —— 同版式不同配色）。
  保持 pHash 单通道是有数据支撑的决定，已写进 README。
- **不要为音频引入三角滤波器组**。频带边界量化跳变只影响「恰好落在频带边界的
  窄带纯音」这种病态输入；换成宽带信号（接近真实音乐频谱）相似度 >0.99。

## 修复：GUI 真实执行报「缺少显式确认」（2026-10-03 晚）
- 报错：`违反安全策略：缺少显式确认：真实执行必须由前端传入 confirmed = true`
- 根因：`src/components/ActionDialog.tsx` 按钮写成 `onClick={() => run(dryRun)}`，
  **把 `dryRun` 当成 `confirmed` 传了进去**。`run(confirmed: boolean)` 是位置布尔参数，
  TypeScript 无从区分两个 `boolean`。
  - 勾着演练 → `run(true)` → `confirmed=true`，恰好蒙对（演练本就不需要确认）；
  - 取消演练 → `run(false)` → `confirmed=false` → 后端闸门拒绝。
  - 结论：**GUI 里真实执行从来就走不通**，不是用户操作问题。
- 修复：
  1. `run` 改名 `executePlan(opts: { dryRun; confirmed })`，改用具名对象参数；
     调用点 `run()` 内两个分支把标志位都写全，杜绝位置参数错配。
  2. 新增「我已核对以上清单，确认执行」勾选项（`acknowledged`），未勾选时按钮禁用，
     让 `confirmed=true` 真正来自用户的显式动作；切回演练会重置该勾选。
  3. 确认区放在清单/汇总**之后**，避免用户看不到完整清单就勾选。
- 后端无需改动：`actions::execute` 的 `!confirmed && !dry_run` 拒绝逻辑本来是对的。
- 验证（GUI 点不了，用 CLI 钉契约）：
  - `--trash`（无 `--yes`）→ 退出码 1 + 该报错 + 文件原封未动；
  - `--trash --yes` → 退出码 3 + 副本清理 + 原件保留。
  - 已把这条契约加成冒烟测试场景 9 的 3 条断言（总共 78 项）。
- 教训：**两个同类型的位置布尔参数是 bug 温床**，改用具名对象。
  以及**只跑「轻松路径」测不出这类问题** —— 演练路径恰好绕过确认闸门，必须正反两侧都断言。

## 环境陷阱（会浪费大量时间）
- macOS 的 `$TMPDIR` 在 `/var/folders/...`，**位于受保护的 `/private/var` 内**，
  扫描根会被正确拒绝。测试工作目录必须放在 `/tmp`。
- `ProtectedPaths` 只锁 `/private/etc` 与 `/private/var`，**不能锁整个 `/private`**，
  否则会把 `/tmp`（→`/private/tmp`）一起误伤。
- **`fileclean` 不带子命令时会启动图形界面并永久阻塞**。写脚本/测试必须显式带 `scan`。
- macOS 没有 `timeout` 命令；Bash 工具里用 `&` 起的后台进程会在该次调用结束时被终止，
  长任务要用工具自身的后台模式。
- `cp -a` 在 macOS 上**不保留硬链接**。需要保硬链接的复制要自己按 (dev, inode) 去重后 `os.link`。
- 管道接 `tail` 时，进程被 kill 会看不到任何输出 —— 调试脚本请直接重定向到文件。

## 修复：多扫描根导致 `Got 5, needed 4`（2026-10-03 傍晚）
- 报错：`数据库错误：Wrong number of parameters passed to query. Got 5, needed 4`
- 根因：`db/cache_repo.rs::load_for_roots` 动态拼 SQL 时用
  `format!("substr(path, 1, ?{}) = ?{}", i + 2, i + 3)` 手算位置参数下标，
  `i=1` 时得到 `?3 / ?4`，**`?3` 被复用** → SQL 只声明 4 个占位符却绑定 5 个值。
  单根（`?1/?2/?3`）恰好正确，所以之前单根冒烟测试全绿、完全没暴露。
- 修复：改用**具名参数** `:cutoff / :len{i} / :root{i}`，名字与值一一对应，彻底免掉下标算术。
- 教训：**SQL 占位符绝不要手算下标**；有多值循环时用具名参数。
  并且**测试必须覆盖「多根」**，单值路径跑不出这类 bug。
- 回归测试：`db::cache_repo::tests`（4 个）已用原始实现验证过会 panic；
  冒烟测试新增场景 2b「多扫描根」，其中一条断言用 `entry.root` 判断跨根
  （不能用 `entry.path` 前缀比较——macOS 上 `/tmp` 会被规范化成 `/private/tmp`）。
- 结果：单元测试 51 passed；端到端 75 项断言全过（原 68）。

## 已知未修（观察项）
- `stats.filesSeen` 计入的是**目录遍历条目**（含目录本身），不是纯文件数。
  两棵各含 1 文件的根 → `filesSeen=4`。UI 上显示为「发现 N 个文件」会偏大。
  属既有口径问题，未在本次修改，待定。
- `cache_repo::purge_root` / `load_for_roots` 的前缀匹配没有分隔符边界检查
  （根 `/tmp/a` 会匹到 `/tmp/ab/...`），但缓存复用还要 size+mtime+inode 全等，
  inode 唯一，故实际不会误复用，影响可忽略。

### 回收站落点：一个依赖环境的假阳性（重要）

冒烟测试 [9. 清理：移入回收站] 报「内容可在回收站中找回」失败。查下来**不是产品缺陷**：

- 文件确实进了系统回收站，但 macOS 的 `~/.Trash` 受 **TCC 保护**，本进程
  `os.scandir` 直接被拒（`PermissionError: Operation not permitted`），`ls` 显示为空。
- 测试原来只把 `HOME` 指向沙箱 —— 但 `$HOME` **只能重定向降级方案**，
  管不住 `trash::delete` 走的系统原生回收站。
- 之前 78/78 通过，是因为当时原生路径恰好被 TCC 挡掉（AppleScript -10004）走了降级。
  **属于依赖环境的假阳性。**

**修法**：新增 `FILECLEAN_TRASH_DIR`（`AppConfig.trash_dir`）。设置后完全不调用
`trash::delete`，直接 `move_into` 指定目录。收益有三：

1. 测试能把「回收站」这一步完全沙箱化，不再往开发者真实废纸篓丢文件；
2. 可以硬断言「找回的内容与原件逐字节一致」——以前断言不了落点；
3. 对 CI / 纯 SSH 场景是真需求（那边系统回收站落点本就不确定）。

配套：`do_trash(path, explicit_dir)` 签名变更；新增单元测试
`explicit_trash_dir_is_used_and_content_survives`（52 个测试）；冒烟测试设
`FILECLEAN_TRASH_DIR` 到沙箱。

**教训**：`HOME` 沙箱化不是万能手段 —— 凡是「落点由系统 API 决定」的行为
（回收站、字体目录、系统缓存），`HOME` 都可能无效。要么给出显式覆盖入口，要么别断言。

### 第三轮：真跑第 5 层，抓出两个「假阳性」

用户请求（界面重构 + 1200×800）此前已完成；本轮是**收尾重验**，结果又抓到两个问题，
都不是应用功能缺陷，而是**验收手段本身不可靠**。

**回归结果**：单元测试 52 passed；端到端冒烟 79 项断言全过；`tsc` + `vite build` 通过
（正式产物 `index-CTgEw5lc.js` 293.90 kB / gzip 91.19 kB，与上轮一致）。

**缺陷 1（真实配置错误）：`vite.preview.config.ts` 缺 `build.rollupOptions.input`。**
Vite 默认把根目录 `index.html` 当入口，所以 `vite build --config vite.preview.config.ts`
一直打的是**生产入口**。铁证：`dist-preview/index.html` 与 `dist/index.html` 引用的产物
文件名**完全相同**（`index-CTgEw5lc.js` + `index-BoVs4173.css`）。也就是说上一轮
「预览入口可构建」的结论是假阳性 —— 预览入口从未被编译过。

- 修法：加 `rollupOptions: { input: "preview.html" }`。修后产物变为
  `preview-Mn3liC1C.js` 303.63 kB（多出的约 10 kB 即 mocks 模块），
  且预览产物含 `预览模式未实现命令` 字样、正式产物为 0 处。
- `verify_tauri_app.sh` 第 5 步相应加强：用 `compgen -G "dist-preview/*preview*.html"`
  断言产物里确实有预览入口，而不是只要「构建成功」就放行。

**缺陷 2（我自己的测量方法错误）：跑到错误页面上做版式检查。**
我访问了 `http://localhost:4175/`，它服务的是**生产入口** `index.html`（无 mocks）。
控制台真实报错：

```
TypeError: Cannot read properties of undefined (reading 'transformCallback')
    at listen (@tauri-apps/api/event.js:140)
    at onProgress (src/api.ts:139)  →  src/App.tsx:68
```

effect 抛错打断了 React 提交，于是点「扫描规则」不换视图。我一度以为这是应用缺陷，
直到 `eval` 出 `typeof window.__TAURI_INTERNALS__ === "undefined"` 才定位到是**入口走错**。
换成 `/preview.html` 后一切正常（`internals=object`、`.settings-nav` 存在、6 个分区齐全）。

- **教训一**：`overflow: []` 连续 6 次全绿、但 `.nav-item` 列表为空 —— 这是「量错页面」的
  典型特征。必须在**同一个 `eval`** 里既断言目标页面已挂载（稳定选择器 + 当前高亮项），
  再断言溢出，否则「全绿」毫无意义。
- **教训二**：`scrollWidth > clientWidth` 对 `<input>`/`<textarea>` 是**固有行为**（内容比
  可视宽度长，控件内部自行滚动），不是裁切。实测该输入框右边缘与父容器**完全齐平**
  （1048 vs 1048），属误报。启发式要排除表单控件。
