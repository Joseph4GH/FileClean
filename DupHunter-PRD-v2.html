1. 背景与问题

1.1 业务背景

个人和中小团队的数字资产涨得比硬盘快。摄影 RAW 加 JPEG 双份备份、视频工程的代理文件和缓存、下载目录堆积、系统镜像和虚拟机快照、NAS 上一年几次的全量备份、iCloud 和 OneDrive 的同步目录，同一份内容往往在盘上共存三五份甚至十份，几十 GB 就这么没了。

文件系统帮不上忙。它只认文件名和路径，IMG_0001.CR2 和 备份/DSC_9123.cr2 在它眼里毫无关系，人眼也比对不出。

市面上能查重的工具不少，问题集中在三处。

  • 只认文件名或大小的，改个名就找不回；认得全的又容易把"同一张照片的两个版本"算成两个，白忙一场。
  • 更麻烦的是删错。Lightroom 目录里的照片被删，下次打开整个目录红掉；Premiere 序列少一个源文件，导出的活儿卡在那儿。
  • 百万文件的盘扫一次要几小时，多数人扫到一半就关掉了。

1.2 痛点与对策

编号 痛点 本产品对策
P-1 找不全。改过名、挪过位置、打包过的相同内容认不出来 内容哈希 + 感知哈希 + 压缩包内检索
P-2 不敢删。删完工程打不开、照片库报错 引用完整性检查 + 回收站或链接替换 + 撤销窗口
P-3 太慢。全盘几小时，改一个文件就得重扫 增量缓存 + 多线程 + 内存映射
P-4 不会选。一堆重复文件，不知道留哪份 智能选择助手，规则化自动标记，一键反向选择
P-5 看不清。只看到两个文件名，没法确认是不是真的一样 缩略图、文本差异、波形、关键帧预览
P-6 不能自动化。NAS 上只能点鼠标一个个删 CLI、会话文件、报告导出，能挂定时任务

1.3 目标（v1.0 起 6 个月）

指标 目标
首次扫描性能 百万文件全量扫描 10 分钟内跑完（NVMe 盘）
增量扫描 二次扫描 1 分钟内出结果
误删事故 0 起。凡触发引用保护或走回收站的，必须能回滚
留存 完成一次有效清理的用户，30 日留存 40% 以上

2. 产品定位

2.1 一句话

一套跑在本地、主打"绝不误删"的重复文件查找与清理工具。

2.2 三个目标

目标 定义 怎么验收
查得全 从字节完全一致到"看着像同一张照片"都能认 精确哈希、模糊哈希、压缩包内、媒体感知四类匹配都支持
认得准 相似度可调，能预览能复核，误报率可控 图片阈值区间 0 到 100，默认 90，人工复核入口常驻
删得稳 任何删除可回滚，不破坏外部引用 默认走回收站或隔离区，受引用文件禁用永久删除

2.3 明确不做

  • 不做云盘网盘在线搜索，那活儿归 OneDrive 和 iCloud 客户端。
  • 不做杀毒、不扫恶意软件。
  • 不做文件恢复，数据恢复交给专业工具。
  • v2 之前不做跨设备同步和多人协作。
  • 不做在线 OCR 比对。所有计算在本地完成，不上传路径，不上传内容。

4. 竞品与我们的做法

竞品 优势 短板
dupeGuru 开源、跨平台、有图片和音乐专用模式 增量扫描弱，界面老，没有引用保护
fclones / jdupes CLI 跑得快，支持硬链接删除 没有预览，没有引用保护，面向极客
VisualDUP / Photo Double 图片视觉相似做得不错 只管图片，Windows 为主，价格高

我们的做法：把"引用完整性检查"和"可撤销的删除"做成信任上的优势，把"增量扫描加感知哈希"做成体验上的优势。

5.2 主流程

扫描：选路径，套过滤规则，遍历文件，按大小预筛，算精确哈希（xxHash128），媒体类再算感知哈希，分桶聚类，跑引用完整性校验，出分组结果。

处置：挑待删项，弹确认（显示占用空间和分组数），选策略（回收站、链接替换、移到隔离区、shred），执行，开 30 秒撤销窗口，落库记一笔。

6. 功能需求

优先级：P0 是 v1.0 上线必备，P1 在 v1.0 或 v1.1 交，P2 排进 v1.x。每条需求带编号，测试按编号拆用例。

FR-01 扫描范围与过滤（P0）

用户可以自己圈定扫哪儿，再套一层过滤，免得一扫全盘、结果几千条没法看。

编号 需求点 优先级 需求描述 验收标准
FR-01-1 扫描源类型 P0 支持本地文件夹、整个驱动器、网络路径（SMB/NFS）、云同步目录（iCloud/OneDrive/坚果云） 四种源都能扫出结果；网络路径支持保存用户名、密码、域
FR-01-2 范围选择 P0 多选手选路径做并集；带"只扫当前层，不含子目录"开关 连选三个目录，重复文件不会进两组
FR-01-3 扩展名过滤 P0 按扩展名包含或排除，支持批量输入（.jpg,.jpeg,.png）和常用预设（图片、文档、音视频、代码） .lnk 等默认进排除项；可切"排除未知扩展名"
FR-01-4 大小范围 P0 支持 min 到 max，单位 B/KB/MB/GB，也认 500M 这种写法 填 10M~ 只统计 10MB 以上的文件
FR-01-5 修改日期 P0 支持"早于 N 天""介于 X 到 Y""最近 N 天" 设 180 天后，结果里不含 180 天内改过的文件
FR-01-6 文件属性 P1 按隐藏、系统、只读属性过滤（黑白名单） macOS 的 .DS_Store、Windows 的 desktop.ini 可单独排除
FR-01-7 跳过规则 P0 自动跳过符号链接自身、系统卷、缓存里已扫过且未变更的条目、被占用的文件 扫到系统目录时弹提示问一句要不要继续
FR-01-8 数量与命名例外 P2 支持"忽略同名文件"，同目录内同名的不算重复 同名同内容同目录的一组不出现在结果里

FR-02 多模式匹配算法（P0）

四级匹配，从字节完全一致到内容高度相似。

编号 需求点 优先级 需求描述 验收标准
FR-02-1 内容哈希 P0 对内容算指纹，算法可选 xxHash128（默认）、MD5、SHA-1、SHA-256；可选"只读头尾 1MB"加速 文件名和路径完全不同、二进制一致的两个文件判为重复；换算法结果可复现
FR-02-2 文件名和大小预筛 P0 先用大小和文件名分桶，快速剔掉大批 大目录里预筛后候选集控制在全量 5% 以内
FR-02-3 模糊匹配，文档 P0 PDF/DOCX/XLSX/PPTX 提取文本层，归一化后比相似度（忽略空格换行和元数据） 同一份文档换个封面和标题还能认出来
FR-02-4 模糊匹配，图片 P1 图片算感知哈希后聚类，见 FR-03 —
FR-02-5 模糊匹配，音视频 P1 抽帧或抽频谱后比对，见 FR-03 —
FR-02-6 匹配模式可切 P0 结果页能切"精确匹配"和"模糊匹配（含相似媒体）"，切完重新聚类 切换后列表立即刷新，不用重扫
FR-02-7 结果分组 P0 同指纹聚成组，组内至少 2 个才显示；组内标出可释放空间 三个同内容文件归一组，显示"可释放 1.2 GB"

FR-03 感知哈希与相似媒体查找（P0 / P1）

解决"同一张照片被裁一下、调个色、压一压、改个尺寸还是同一张"这件事。

编号 需求点 优先级 需求描述 验收标准
FR-03-1 图片 dHash P0 差值哈希（64 位）认轻微编辑过的同图 同一张 PNG 另存成 JPG 再压一轮仍能匹配
FR-03-2 图片 pHash P0 感知哈希（DCT，64/128 位）认裁剪、调色、缩放、轻度水印 缩到 50% 再拉回来、加个滤镜，还能匹配
FR-03-3 阈值调节 P0 0 到 100 的滑块，默认 90，实时显示当前阈值下的匹配对数，滑块动完重新聚类 阈值从 90 拉到 99，匹配组明显变少，数字给到位
FR-03-4 音乐声学指纹 P1 用 Chromaprint/AcoustID 那套思路，认不同码率、不同标签、音量归一化后的同一首歌 320kbps 和 128kbps 的同名文件判为重复
FR-03-5 视频帧比对 P1 按间隔抽关键帧算帧级 pHash，整段加权算相似度 转过码（H.264 到 HEVC）的同源视频判为重复
FR-03-6 性能兜底 P0 感知哈希只在"同类型加相近大小"的候选对上算，不做 O(N²) 全比 10 万张图开模糊匹配，90 秒内算完

FR-04 安全删除（P0）

这是产品的底线。任何一次删除都得能收回，默认不直接抹掉数据。

编号 需求点 优先级 需求描述 验收标准
FR-04-1 回收站（默认） P0 Windows 送回收站，macOS 送废纸篓，Linux 送 ~/.local/share/Trash 删完在废纸篓里能看见，30 秒内可撤销并回到原路径
FR-04-2 硬链接和符号链接替换 P1 删副本后在原路径造一个指向保留文件的硬链接（同分区）或符号链接（跨分区）；删之前校验目标没被引用 删完原路径照样能打开，不占双份空间；跨分区自动降级成软链并说明原因
FR-04-3 移到隔离文件夹 P0 提供"移到指定目录"策略，比如 ~/DupHunter-Quarantine/日期/，方便人看一眼再决定 文件落位准确，按 session 分目录，不堆一层
FR-04-4 永久删除 P1 支持永久删除（必要时调 shred/SDelete），前提是文件没被工程引用、不是系统文件，删之前列清单二次确认 被引用或属于系统目录时，永久删除按钮置灰并说清原因
FR-04-5 撤销 P0 全局撤销栈（Ctrl+Z / Cmd+Z），至少能撤回最近 3 批删除 撤销后文件回原路径，权限和时间戳基本保持
FR-04-6 删前确认 P0 执行前弹面板，列分组数、文件数、可释放空间、待删清单（带缩略图） 不点确认，一个文件都不动
FR-04-7 空间预估 P0 列表顶部实时显示"当前可释放空间"，勾选时跟着动 勾 5 个文件，顶部数字同步变
FR-04-8 回收站空间告急 P2 目标回收站或隔离区快满时提示换隔离目录 —

FR-05 结果预览与对比（P0）

删除之前让用户看见东西，把盲删变成确认。

编号 需求点 优先级 需求描述 验收标准
FR-05-1 图片缩略图 P0 网格视图用大缩略图，列表视图用小图加文件名、大小、路径、时间 HEIC、RAW（CR2/NEF/ARW/RW2）、WebP、AVIF 都能出缩略图
FR-05-2 并排对比 P0 同组两张图并排放，可切"差异高亮" 差异区域能高亮出来
FR-05-3 文本差异 P0 文本类文件逐行 diff，高亮增删行 两个 txt/md/json 能 diff
FR-05-4 音频波形 P0 显示波形，点哪播哪，支持 A/B 双轨对比 能同时播 A 和 B 听差别
FR-05-5 视频关键帧 P1 自动抽首帧和中段帧，左右切换对比 —
FR-05-6 元信息面板 P0 显示路径、大小、创建和修改时间、EXIF（相机、镜头、焦距、ISO、拍摄时间）、文件属性 摄影文件能看到 EXIF 和拍摄时间
FR-05-7 外部程序打开 P1 右键"用系统默认程序打开" —

FR-06 智能选择助手（P0 / P1）

用规则替用户想"这组留哪个"，不用一组组点。

编号 需求点 优先级 需求描述 验收标准
FR-06-1 内置保留策略 P0 六种：保留最新创建的、保留最早创建的、保留路径最短的、保留文件名最长的、保留位于指定文件夹的（比如 原片 目录）、保留体积最大的 每种规则能一键应用到全量或当前视图
FR-06-2 组合规则 P1 多条规则按优先级排，命中即停，也支持自定义表达式 能跑通"优先保留 RAW，组内没有 RAW 就留分辨率最高的 JPG"
FR-06-3 逐组决策 P0 除批量规则外，支持"这组就这么选，同样选择应用到全部" 勾一次能批量下发
FR-06-4 反向选择 P0 一键全选、反选、全不选，以及"选中所有非首选项" 反选后待删项等于没标保留的那批
FR-06-5 规则复用 P1 规则集存成配置文件，能复用也能发给同事 —
FR-06-6 标记可视化 P0 保留项打绿标，待删项标红置灰，和删除面板状态一致 —
FR-06-7 危险操作保护 P0 一组里全标了保留时，禁止对该组执行删除，提示"这组没有可清理项" —

FR-07 引用完整性保护（P0）

删一个文件之前，先知道有没有别的软件正指着它用。

编号 需求点 优先级 需求描述 验收标准
FR-07-1 项目引用检查 P0 扫描并解析常见项目文件和索引文件，标出其中引用的素材路径：Lightroom（.lrcat/.lrcatalog 的 SQLite）、Premiere（.prproj）、After Effects（.aep）、Logic（.logicx）、iTunes（.itl）、MySQL 数据目录、Docker 与虚拟机镜像 被 Lightroom 目录引用的照片显示"被引用 · Lightroom"，默认不可选删
FR-07-2 快捷方式和别名 P0 解析 Windows .lnk、macOS 别名、Linux 软硬链接，建立"链接到目标"的映射；目标在待删列表时，链接本身算保护项 软链的目标进了待删，软链变红且不可选
FR-07-3 系统文件保护锁 P0 自动排除并锁定系统关键目录：Windows 的 Windows、Program Files、System32、AppData；macOS 的 /System、/usr、/Library、~/Library 用户没法对这些目录里的文件做永久删除
FR-07-4 保护级别 P1 三档：严格（被引用即保护）、宽松（被引用只提示）、自定义（用户自己导保护路径和扩展名清单） —
FR-07-5 引用来源可见 P0 列表里显示引用来源标签（哪个项目、哪个快捷方式），点标签能跳到引用位置 —
FR-07-6 基准快照对比 P2 以历史扫描为基准，只标新增或消失的文件 —

FR-08 高性能与增量扫描（P0）

面向百万级文件的工程能力。

编号 需求点 优先级 需求描述 验收标准
FR-08-1 多线程异步 IO P0 扫描和哈希阶段并行，吃满 NVMe 的高并发；IO 和 CPU 解耦 百万文件约 200GB，首次扫描 10 分钟内（NVMe，基线见附录 B）
FR-08-2 增量缓存 P0 用路径加 inode/dev 加 mtime 加 size 加部分哈希当键，缓存算过的指纹；二次扫描只处理新增、变更、缺失的文件 全量后再跑一次 1 分钟内出结果，且结果一致
FR-08-3 内存映射 P0 大文件（4K 视频、ISO 镜像、Docker 镜像）用 mmap 零拷贝读，不整块进内存 扫一个 80GB 的 ISO，内存峰值 512MB 以内
FR-08-4 大文件优化 P0 可选"头尾哈希"（首尾各读 1MB）加速超大文件，精度下降，UI 上要标出来 —
FR-08-5 进度与中断 P0 实时进度（已扫数量、当前阶段、预估剩余），可暂停、继续、中断；断了能接着扫 中途停掉再跑，从缓存里的断点续
FR-08-6 结果索引 P0 结果落 SQLite，支持按组、路径、大小、时间排序筛选和搜索 10 万组结果里搜索响应 200ms 内
FR-08-7 资源上限 P1 用户可设最大并发线程数和内存上限，照顾低配机器 —

FR-09 自动化与工作流集成（P1 / P2）

编号 需求点 优先级 需求描述 验收标准
FR-09-1 命令行 P1 提供 dup 子命令：scan（路径、过滤、算法、阈值）、report（导出）、delete（按报告或规则，配 --dry-run）、session（保存和恢复） --dry-run 只出计划不产生改动；脚本调用有退出码，0 成功、2 冲突
FR-09-2 会话保存恢复 P1 扫描中断能续；结果存成 .dhsess 项目文件，以后加载接着改 session 能跨机器传，路径对不上时给提示
FR-09-3 报告导出 P0 导出 CSV、HTML、XML、JSON，字段含路径、大小、哈希、相似度、分组 ID、可释放空间 CSV 用 Excel 直接打开不乱码，BOM 可开关
FR-09-4 报告用途 P0 报告要能过审计和合规：带扫描时间、机器信息、规则参数、结果说明 —
FR-09-5 定时任务 P2 给出群晖、威联通的 cron 写法和 GitHub Actions 示例 —
FR-09-6 无人值守清理 P2 支持"扫描、按规则标记、送隔离区"一条流水线跑完 —

FR-10 特殊格式支持（P1 / P2）

编号 需求点 优先级 需求描述 验收标准
FR-10-1 压缩包内扫描 P1 不解压直接列 ZIP、RAR 1-5、7Z、TAR.GZ 的内部条目，按内容指纹参与去重；提供"解压后比对"开关（--explode） 两个内嵌了同一份 PDF 的 ZIP 判为重复组
FR-10-2 RAW 加 JPEG 配对 P1 摄影专用：按主文件名一致把 IMG_0001.CR2 和 IMG_0001.JPG 归成一个媒体单元，不算彼此重复；单元整体保留或清理 同目录的 RAW 和 JPG 不会互相进对方的重复组
FR-10-3 配对策略可配 P2 扩展名映射表可改（比如 .CR2 对 .JPG、ARW 对 .JPG），是否跨目录配对也可配 —
FR-10-4 元数据副本 P2 用 EXIF 哈希（拍摄参数加时间）认"同一次拍出来的多份导出" —

7. 数据模型与存储

7.1 表结构（SQLite）

表 作用 关键字段
file_index 文件索引 路径、名称、扩展名、大小、mtime、ctime、inode、dev、mode（隐藏/系统）、哈希算法、哈希、pHash、部分哈希、状态（新增/扫描中/已扫/已删/出错）
hash_cache 增量缓存 路径键（路径+inode+size+mtime）、哈希、计算时间
duplicate_group 重复分组 分组 ID、匹配模式（精确/相似/媒体）、阈值、组内文件数、浪费字节、创建时间
group_member 组内成员 分组 ID、文件 ID、标记（保留/删除）、是否受保护、被谁保护
reference_link 引用关系 来源路径（项目文件）、目标路径、类型（lrcat/prproj/lnk/alias/symlink/hardlink）、解析时间
session 会话 会话 ID、名称、参数 JSON、状态、创建时间、中断时间
action_log 删除审计 记录 ID、会话 ID、动作类型、原路径、新路径、是否已撤销、撤销时间
rule_set 规则集 规则集 ID、名称、规则 JSON、是否默认

7.2 位置与清理

索引库默认放在：Windows %LOCALAPPDATA%\DupHunter\cache.db；macOS ~/Library/Application Support/DupHunter/cache.db；Linux ~/.local/share/duphunter/cache.db。CLI 可用 --config-dir 改位置。

索引能单独清（"只清缓存，不动用户数据"），另有"清空全部历史"的入口，两个动作要讲清区别再确认。隔离目录按会话分：~/DupHunter-Quarantine/YYYYMMDD-HHmmss/。

8. 非功能需求

8.1 性能

指标 目标
首次扫描吞吐（NVMe，普通文件） 每分钟 30 万文件以上
增量扫描 每分钟 200 万文件以上
内存峰值（100 万文件） 600MB 以内
单个大文件（≥50GB） mmap 流式处理，不会因为一个文件 OOM
结果检索 10 万组以内 200ms 响应
冷启动到可交互 2 秒内

8.2 兼容性

类别 要求
系统 Windows 10/11（x64、ARM64）、macOS 12 以上（Intel 和 Apple Silicon）、Linux（glibc 2.31+，x64/ARM64）
文件系统 NTFS、APFS、HFS+、exFAT、ext4、FAT32，以及 SMB/NFS 挂载盘
技术选型 核心建议 Rust，GUI 用 Tauri 2 加系统原生 WebView，包体小且三平台一致
权限 扫用户目录不需要管理员/root；访问网络路径时按需提权

8.3 安全与隐私

  • 全程本地处理，文件路径和内容一个字节都不往外发。可选的匿名统计默认关掉，打开也要写清楚。
  • 删除走系统原生通道（回收站 API），不自己实现 delete。
  • 提供隐私模式：日志、报告、崩溃信息里不出现绝对路径和文件名。

8.4 可用性与可维护性

  • 全键盘可操作，配快捷键；首次启动给 5 步引导。
  • 出错要说人话：权限不够、文件被占、坏道、断网，都要给出具体路径和原因，不能静默吞掉。
  • 日志分 debug/info/warn/error 四级，CLI 支持 --verbose。

9. 界面与交互

页面 关键元素

14. 验收标准（Definition of Done）

  1. 所有 P0 需求 100% 实现，验收用例全过。
  2. Windows 11、macOS 14（Apple Silicon）、Ubuntu 22.04 上扫同一个目录，重复组的结论一致。
  3. 100 万文件、200GB 以上的压力测试达到附录 B 的性能基线。
  4. 随机执行 200 组删除，撤销成功率 100%，误删 0 起。
  5. 连续跑 24 小时扫描任务不崩，无 P0/P1 级崩溃和内存泄漏。
  6. 隐私评审通过：全量抓包无外发请求（用户显式打开检查更新除外）。

附录 A 名词表

术语 含义
内容哈希 对文件二进制内容算的摘要（xxHash、MD5、SHA），内容一样哈希就一样
感知哈希 pHash 基于 DCT 的感知摘要，容忍缩放、压缩、调色，容不让由阈值说了算
dHash 差值哈希，取相邻像素灰度差生成 64 位，对轻微编辑很敏感
声学指纹 从音频波形提的听觉指纹（比如 Chromaprint），忽略码率和元数据差异
硬链接 同一文件系统里多个目录指向同一个 inode，删一个不影响数据
符号链接 路径级引用，能跨分区，但源文件没了它就失效
macOS 别名 / Windows 快捷方式 指向原文件的引用文件，原文件没了它们就废
引用完整性 删之前确认文件没被任何项目、链接或系统组件指着用
增量扫描 靠上次的缓存只处理变更文件的扫描方式
媒体单元 RAW 加同名 JPEG 当一个整体看，不算彼此重复

领域 建议
语言 Rust，做核心引擎，性能、内存、跨平台都省心
GUI Tauri 2 加原生 WebView，包体小
算法 xxHash128 做精确匹配，pHash/DCT 做图片，Chromaprint 做音频，抽样帧 pHash 做视频
